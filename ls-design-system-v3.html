Design Decisions

All resolved conflicts documented
✓ 1. Font: Inter only

DM Sans deprecated. Inter is already in production, no change needed.

✓ 2. Primary color: #005b94 (locked)

Full 50–900 scale generated. Semantic aliases defined so changing this value in one place updates everything.

✓ 3. Sidebar: White, 256px

Consistent with the existing Venue Manager pattern. White sidebar is the established pattern for operator-facing views.

✓ 4. Nav structure: Collapsible groups (13px/700 group headers)

P2 pattern adopted. Resolves P1 vs P2 inconsistency.

✓ 5. Header CTAs: LiquidAI always present

Persistent on all pages. Secondary actions context-dependent to its left.

✓ 6. Pending vs Pending Review: Two distinct states

Pending (orange) = external action needed. Pending Review (blue) = awaiting LS review.

Open Issues

Flagged for team review before production
⚠ 1. Draft badge improved but needs team confirmation

Changed from #005b94 (identical to Pending Review) to #94a3b8 slate gray. Confirm this is acceptable.

⚠ 2. Intake / Evaluation / Contracting / Pending Review all share #005b94

Four distinct states look identical. Intake and Evaluation could be distinguished with navy or a lighter blue to reduce visual ambiguity in the workflow stepper.

⚠ 3. Table header 14px = body text 14px

Reproduced from prototype exactly. Recommend considering 12px or weight 500 to create clearer column label vs. data hierarchy.

⚠ 4. Modal header color = page header color = primary button

All three use #005b94. No visual differentiation between a page context and a modal overlay context. Low risk for now, flagged for future refinement.

⚠ 5. Dark mode not defined

Token structure is semantic-alias-ready for dark mode. No dark values defined yet. If this is needed, the alias layer makes it straightforward to add.

Focus & Keyboard rules
All interactive elements have :focus-visible outline: 3px solid rgba(0,91,148,0.35)
Modals trap focus. Escape closes. First focusable element receives focus on open.
Dropdowns: Arrow keys navigate, Enter selects, Escape closes
Checkboxes/radios: Space to toggle, Tab to move between
Tables: Tab to navigate columns, Enter to open row detail
Date picker: Arrow keys navigate days, Enter selects
⚠ Warning badges fail WCAG AA

White text on #ffa500 (orange) has a 2.1:1 contrast ratio — below the 4.5:1 AA standard for normal text. Recommend switching to dark text (#6b3500) on warning badges, or using a slightly darker orange (#e07800) as the background.

Usage Guidelines

When to use each component — decision rules for developers and designers
Buttons — when to use which variant
Button decision rules
Variant
Use when
Never use when
The single most important action on the page or in a modal. Save Changes, New Requirement, Upload, Mark Paid.
There are two Primary buttons side by side. There is no clear primary action. In a destructive confirmation dialog.
An important action that isn't the primary one. Export Data, Add Funding Source, Duplicate. Pairs with Primary.
As the only button on a page — escalate to Primary. For destructive actions — use Danger.
Cancel, dismiss, or navigate back. Always pairs with a more prominent button. Never stands alone as the primary action.
As the only button. For navigation links — use a text link instead.
Irreversible destructive actions only. Delete, Remove. Always in a Confirmation Dialog, never inline.
For Archive — that's reversible, use Secondary. For anything that can be undone.
Icon
In table rows for edit/delete where space is tight. In toolbars with tooltips explaining the action.
Without a tooltip. As the primary CTA on a page. When a text label would fit — labels are always clearer.
Badges — usage rules
When to use badges vs. other patterns
Use badges for state that changes over time. Active → Expiring Soon → Expired is a lifecycle — badges communicate where a license is in that lifecycle at a glance.
One badge per row in tables. If you need two status indicators, one is probably redundant. Reconsider your data model.
Don't use badges for permanent attributes. "License · Direct" or "LiquidSpace" are types, not states. Use plain text in a muted color instead.
Don't stack workflow stage badges in tables. The stepper component exists for showing stage. In a table, a single stage badge is sufficient.
Modal vs. Confirmation Dialog — decision rule
Which modal pattern to use
Use Full Modal when
→ The action requires filling in a form with 3+ fields
→ The content needs tabs to stay organised
→ You're showing related data alongside the action (documents, team, workflow)
→ The user will spend more than 30 seconds in the modal
Use Confirmation Dialog when
→ Confirming a single irreversible or significant action
→ Asking the user to verify before proceeding (Delete, Archive, Mark Paid)
→ The message fits in 1–2 sentences
→ There are only two choices: confirm or cancel
Empty states — which variant to use
Decision tree
No data yetUser has never created any records in this view. Show the "no data yet" variant with a primary CTA to create the first record. Don't show filters or search.
No resultsFilters or search are active but return nothing. Show the "no results" variant with a "Clear filters" ghost button. Never show a CTA to create new data — they probably mis-filtered.
ErrorData failed to load due to a network or server error. Show the error variant with a "Try again" secondary button. Include a reference to support if the error persists.

Writing Guidelines

Voice · labels · button text · error messages · empty states
Voice and tone
How LiquidSpace Ops speaks
The voice is
Direct— Say what happens, not what the system is doing. "Saved" not "Your changes have been successfully saved to the database."
Precise— Use specific numbers and names. "3 licenses expiring" not "some licenses expiring."
Calm— Errors are recoverable. Warnings are informational. Don't use alarm language for routine states.
Professional— This is a financial and legal ops tool. No exclamation marks, no emoji, no "Oops!"
The voice is not
Casual— No "Hey there!", "Let's get started!", or "Looks like…"
Technical— No error codes, stack traces, or internal IDs in user-facing messages.
Alarming— Don't use "Warning!" or "Critical!" for non-critical states like "Expiring Soon."
Apologetic— "Sorry, something went wrong" adds no value. State the problem and the action.

Empty state copy — formula
Empty state writing patterns
No data yet
Title:No licenses yet
Body:Get started by uploading your first license or lease agreement.
CTA:Upload License (Primary)
Rule: Short, instructional. Always a CTA to create. No apology.
No results
Title:No results found
Body:No licenses match your current filters. Try adjusting your search.
CTA:Clear filters (Ghost)
Rule: Never suggest creating data. The data probably exists — they're mis-filtered.
Error
Title:Failed to load
Body:Something went wrong loading your licenses. This is usually temporary.
CTA:Try again (Secondary)
Rule: Calm. Actionable. Suggest it's temporary. Never show technical details.

How components work together — standard page compositions
Standard page anatomy
Every ops page uses this structure in this order
1
Page Header
Always present. Title + subtitle + LiquidAI button + optional secondary action. Background: #005b94.
2
Stat Cards — optional
Present when the page has summary metrics worth highlighting at a glance. 3–4 cards maximum. Not every page needs them.
3
Filter Bar — required if table is present
Search + filter chips on the left. Primary CTA (create/upload) on the right. Never put the primary CTA elsewhere on a table page.
4
Data Table
The primary content. Row click opens the Full Modal. Checkbox column enables bulk selection. ··· menu for row-level actions. Always ends with Pagination.
5
Pagination
Always right-aligned. Always shows record count on the left ("Showing 1–20 of 116 licenses"). Default page size: 20 records.
Modal tab anatomy
Standard tab order and contents for detail modals
Tab 1 · Summary
Core record fields. Editable form. Save / Cancel in footer. This is the default tab on open.
Tab 2 · Workflow
Stepper + task list + progress. Agent task outputs. Read-only stage indicator.
Tab 3 · Team
Human members + AI agents assigned to this record. Add/remove team members.
Tab 4 · Documents
Uploaded files. Upload button. File name, size, uploader, date. Download/delete per file.
Toast timing and stacking
Toast rules
Auto-dismissSuccess toasts dismiss automatically after 4 seconds. Info toasts after 6 seconds.
PersistentWarning and Danger toasts do not auto-dismiss. The user must acknowledge them.
StackingMaximum 3 toasts visible at once. New toasts push older ones up. Oldest dismisses first if limit is reached.
PositionAlways bottom-right, 24px from edges. Never overlap the primary content or the sidebar.
